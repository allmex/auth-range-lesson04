## 一、这个项目是干什么的

第四课的作业：靶场 App 里被老师预置了一道**卡密（授权码 / 激活码）校验障碍**，
打开后需要输入正确的卡密才能进入主功能。

**任务：逆向分析这两个靶场，绕过老师设置的卡密校验障碍。**

一句话流程：`装上看现象 → 抓字符串找线索 → 反编译定位校验点 → 动态验证 → 改逻辑绕过 → 回归测试`。

## 三、已知结构情报（开工前先读）

已经先扫过一遍包结构，直接给你结论，省掉一轮摸索：

### 靶场 1
- **8 个 dex**，纯 Java/Kotlin 层，**没有 `lib/` 目录**（无 native so）。
- `assets/` 里塞了 **863 个文件**，是 Web 前端资源（`assets/public/...`）。
- 顶层有 `kotlin/`、`org/`。
- **判断**：这是个 Capacitor 打包的 Web 壳 App，业务逻辑大概率在 **JS** 和 **Java Bridge** 两侧。
- **打法**：
  1. 先翻 `assets/public/` 下的 JS，很多卡密校验会直接写在前端（最容易的一档）；
  2. 再 jadx 打开 8 个 dex，搜 `卡密 / 激活 / license / key / auth / verify / vip`。

### 靶场 2
- **3 个 dex** + `lib/arm64-v8a/` 下 **15 个 so**（uni-app / weex / freso 全家桶）。
- **`assets/39285EFA.dex` 与 `lib/arm64-v8a/lib39285EFA.so` 同名** —— 这是**最高优先级的线索**，
  高度怀疑是自定义的**壳 / 动态加载的 dex / native 校验模块**，建议第一个查它。
- `assets/apps/__UNI__66044A6/www/` 是 uni-app 的前端代码（`app-service.js`、`pages/index/index.css` 等）。
- **打法**：
  1. 先看 `app-service.js` 里的业务 JS（uni-app 的校验经常写在 JS 层）；
  2. 再啃 `lib39285EFA.so` + `assets/39285EFA.dex` 这一对，用 IDA/Ghidra 看 so 的导出函数与 JNI 注册；
  3. 只给了 arm64，注意你的分析环境/真机是否兼容。

## 五、推荐分析路线（按这个顺序走，别跳步）

1. **先看现象**：装上跑一遍，故意输错卡密，把**报错提示语**一字不差抄下来。
   —— 这句提示语就是你后面全局搜索的**钥匙**。
2. **搜字符串**：jadx 里全局搜报错提示语、`卡密`、`激活`、`license`、`verify`、`checkKey`、`vip`。
3. **定位校验点**：顺着字符串找到调用它的函数，往上追**调用链**，找到真正的判断分支（通常是 `if` + `boolean` 返回值）。
4. **判明校验类型**：
   - 本地算法 → 可以逆出算法，写注册机；
   - 联网校验 → 抓包，看请求/响应，配合 Frida 改返回值。
5. **动态确认**：Frida hook 那个判断函数，打印入参和返回值，确认它就是卡密校验的唯一入口。
6. **实施绕过**（三选一，难度从低到高）：
   - 改 JS（靶场大概率有效）；
   - 改 smali：把 `if-nez` 改成 `if-eqz`，或直接 `return true`；
   - Hook：Frida 脚本强制返回合法值（不用改包）。
7. **回编译 → 签名 → 安装 → 回归测试**：确认能进主功能，且没有其它暗桩（比如二次校验、签名校验、防篡改）。

> 小技巧：改完如果闪退或卡在启动页，八成是还有**签名校验 / 完整性校验**，优先搜 `signature`、`getPackageInfo`、`SHA1`、`crc`。
